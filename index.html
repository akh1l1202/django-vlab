Git Repository Management for a Django Project

Aim

To understand and implement professional source code version control workflows specifically tailored for a Python/Django web application using Git, including repository initialization, ignore rule formulation, migration file management, feature branching, and merge conflict resolution.

Learning Objectives

After completing this virtual lab experiment, students will be able to:

LO 1 Initialize & Structure a Git Repository for Django: Set up a clean Git tracking environment for standard Django project layouts without tracking generated artifacts or virtual environments.
LO 2 Formulate Production-Grade .gitignore Rules: Safeguard sensitive credentials (.env, SECRET_KEY), avoid local database corruption (db.sqlite3), eliminate binary virtual environments (venv/), and ignore bytecode (__pycache__/).
LO 3 Manage Django Schema Migrations in Version Control: Understand why schema migration files are immutable historical records, how they relate to models.py, and how to avoid split migration heads across team members.
LO 4 Implement Collaborative Branching (Git Flow): Create, switch, and maintain isolated feature branches (e.g., feature/polls-app) before merging them back into the main branch.
LO 5 Diagnose & Resolve Merge Conflicts: Identify standard Git conflict markers (<<<<<<<, =======, >>>>>>>) in Django configuration files such as mysite/urls.py and settings.py, and resolve them cleanly.
LO 6 Apply Semantic Commit Hygiene & Tagging: Practice conventional commit conventions (feat:, fix:, chore:) and create annotated release tags (e.g., v1.0.0) for deployment readiness.
